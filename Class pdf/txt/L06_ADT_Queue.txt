Notion de Queue (File)
• Une file est une structure linéaire permettant de
  stocker et de restaurer des données selon un
  ordre FIFO (First In, First Out ou « premier
  entré, premier sorti »)
• Liste dans laquelle seul l’insertion et la lecture se
  font à des extrémités opposées :
   • Les insertions (enfilements) se font à une extrémité
     appelée queue de la file.
   • Les suppressions (défilements) se font à l'autre
     extrémité appelée tête de la file.

• Synonymes : file de priorité, queue.

Implémenter une file :
Les deux grandes alternatives
• Représentation contiguë :
   • Les éléments de la file sont rangés dans un tableau (simple ou circulaire)
   • Deux entiers représentent respectivement les positions de la tête et de la
     queue de la file
• Représentation chainée :
   • Les éléments de la file sont chaînés entre eux
   • Un pointeur sur le premier élément désigne la file et représente la tête de
     cette file
   • Un pointeur sur le dernier élément représente la queue de file
   • Une file vide est représentée par le pointeur NULL

Implémenter une file à priorité :
Le principe du Heap
• La structure fondamentale d’une file à
  priorité est un arbre binaire avec la
  condition qu’un nœud est l’élément le
  plus prioritaire de tous ses
  descendants (un Heap).
• Trois alternatives :
   • Arbre binaire complet réel
   • Arbre binaire complet dans un tableau
   • Arbre binaire complet dans une liste
     chainée
• Note : un arbre binaire est complet si
  tous les niveaux sont pleins, excepté le
  dernier niveau. Un niveau h peut avoir
  au max 2h

Représenter un Heap avec un tableau
• Représentation typique
• Les éléments sont rangés dans
  un tableau avec les conditions ci-
  dessous :
• Pour un élément d’indice i, ses
  enfants sont stockés aux indice
  2*i (gauche) et 2*i+1 (droit)
• La racine est l’élément le plus
  prioritaire.

Implémenter un Heap avec un tableau :
Opération insert() et heapify_up(i)
• L’opération insert (ou push)
  permet d’insérer un nouveau
  item dans la file dont il faudra
  trouver la bonne position afin de
  respecter l’ordre dans le heap.
• L’opération insert ajoute le
  nouveau item à la fin du tableau
  et est toujours suivie de
  l’opération heapify_up(i) qui
  permet de rétablir l’ordre en
  comparant le nœud avec sont
  parent de façon récursive en
  commençant par le nouvel item
  ajouté.

Implémenter un Heap avec un tableau :
Opération remove() et heapify_down(i)
• remove (ou pop) permet de retirer
  du heap (la file à priorité)
  l’élément le plus prioritaire, i.e, la
  racine.
• La racine est remplacée par le
  dernier éléments dans le tableau
  (le dernier niveau de l’arbre, le
  plus droite).
• Le remplacement de la racine
  provoque une incohérence dans le
  principe du heap et il faut le
  réarranger en invoquant
  l’opération heapify_down() qui
  remplace un nœud racine par l’un
  de ses fils de façon récursive
  jusqu’en bas de l’arbre.

    priority-queues-using-binary-heaps/

Implémenter un Heap avec un tableau :
Ordre de grandeur de la hauteur d’un heap
• Un heap qui stocke n clés a une hauteur h = O (log2 n)
• Preuve:
   • Nombre total des nœuds dans un arbre binaire complet de hauteur h est comme suit:
     n = 1 + 2+ 4 + ..+ 2h
   • Nous savons que 1 + 2+ 4 + ..+ 2h = 2(h+1) -1 . Ainsi, n = 2(h+1) -1
   • Donc hauteur h = log2(n + 1) − 1
   • Par conséquent, h est de O(log n) en pire cas pour beaucoup de genres d’arbres de
     recherche équilibrés ( AVL, rouge-noir, arbre 2-3-4, etc.)
Implémenter un Heap avec un tableau :
Complexité des opérations
• Les opérations prennent un
  temps proportionnel à la
  hauteur (nombre de niveau)
  de l’arbre.
• L’opération heapify réalise à
  chaque étape un certains
  nombre d’opérations en un
  temps constant.
• Ainsi, insert, remove sont
  tous les deux en O(log2 n).
