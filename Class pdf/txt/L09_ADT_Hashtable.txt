Principe d’une table de hachage:
• La table de hachage (hash table, hash
  map) est une structure de données qui
  implémente un TAD dictionnaire
  (tableau associatif), une structure qui
  (map) fait correspondre des clés à des
  valeurs.
• Une table de hachage utilise une
  fonction de hachage pour calculer un
  index, également appelé code de
  hachage, dans un tableau de
  compartiments ou d'emplacements
  (buckets or slots), à partir duquel la
  valeur associée à la clé peut être
  retrouvée.
• The values returned by a hash function are called hash values, hash
  codes, hash sums, or simply hashes.
Fonction de hachage :
Définition
• Inventée en 1953 par Luhn
• Idéalement, la fonction de
  hachage associe chaque clé à une
  position unique dans un tableau
  de stockage.
• La plupart des hash tables
  utilisent une fonction de hachage
  imparfaite, ce qui peut conduire
  à des collisions entre plusieurs
  clés qui ont un même code de
  hachage (les détails plus loin).
                                      https://en.wikipedia.org/wiki/Hash_function
Fonction de hachage :
Le principe
• Principe :
   • Utiliser une table T de taille n << |U| (U est le domaine/univers des clés)
   • Stocker l’élément x a la position h(x.key), ou h est une fonction de hachage :

• Une fonction de hachage
  est une fonction h qui,
  pour chaque élément x de
  l’ensemble, calcule une
  valeur h(x.key) comprise
  entre 0 et N-1
  correspondant à un indice
  du tableau de dimension N.

Fonction de hachage:
Une bonne fonction de hachage
• To achieve a good hashing mechanism, It is important to have a good
  hash function with the following basic requirements:
   • It should be as uncomplicated as possible and fast to compute and must not
     become an algorithm in itself, e.g., a single mathematical or bitwise operation.
   • Uniform distribution: It should provide a uniform distribution across the hash
     table and should not result in clustering.
   • Less collisions: Collisions occur when pairs of elements are mapped to the
     same hash value. These should be avoided.
      • Irrespective of how good a hash function is, collisions are bound to occur.
      • Typically not possible because all of the keys are not known in advance
Collision :
Définition
• Collision : lorsque deux clés distinctes
  k1 et k2 donne la même position dans
  le tableau de stockage avec la fonction
  de hachage h : h(k1) = h(k2)
• Cela se produit toujours lorsque le
  nombre de clés observées est plus
  grand que la taille m du tableau T :
   • |K| > m
• Très probable, même lorsque la
  fonction de hachage repartit les clés
  uniformément.
Résolution de la collision:
Deux familles d’algorithmes
• La hash table possède un tableau interne qui stocke les valeurs des clés.
• La notion d’adresse signifie la position à laquelle la valeur sera stockée.
• Open hashing/Closed addressing/separate chaining : Aucune valeur n’est
  stockée dans le tableau interne, mais plutôt dans une structure auxiliaire
  (appelée aussi Bucket), ex., une liste séparée (séparée du tableau interne). Le
  terme ‘Open’ fait référence à la liberté de quitter le tableau interne pour stocker
  les valeurs associées aux différentes clés. Le terme ‘Closed’ signifie qu’il est pas
  autorisé de replacé la valeur dans un autre endroit du tableau interne.
• Closed hashing/Open addressing: le tableau interne est la seule structure de
  stockage. Chaque valeur est stockée dans le tableau interne. Ceci est possible
  seulement si on autorise un certain adressage ouvert (Open adressing) qui
  permet de trouver, s’il y a collision, une autre place dans le tableau interne à la
  nouvelle valeur ajoutée.

 • En cas de collision, le tableau

Complexité des opérations de l’hachage ouvert
• Comme il y a une liste simple
  pour chaque clé qui s’occupe de
  stocker les différentes valeurs
  associées à cette clé, la
  complexité des opérations de
  base (insertion, recherche et
  suppression) sont toutes en O(n).
• On peut diminuer cette
  complexité si l’on choisisse une
  représentation moins couteuse
  qu’une simple liste (liste triée,
  etc.)
Résolution de la collision:
Hachage fermé – Linear Probing
• Principe : on cherche la prochaine place libre dans le tableau pour accueillir
  la nouvelle valeur.
• La séquence de recherche est :
   • 1er probe: h(k) mod table_size
   • 2ème h(k)+f(1) mod table_size
   • 3ème h(k)+f(2) mod table_size
   • Etc.
• Linear probing : f(i) = i
• Quadratic probing : f(i) = i2

• Note: Une longue séquence de
  probes peut être couteuse.
Résolution de la collision:
Hachage fermé – Linear Probing
• On cherche à replacer
  l’élément en collision
  ailleurs dans le tableau en
  appliquant une fonction de
  re-hachage qui calcule un
  nouvel indice et ceci
  jusqu’à ce que la nouvelle
  entrée soit libre. Ce choix
  conduit à une dégradation
  des performances dès que
  le taux de remplissage de la
  table dépasse 90%.

Adressage ouvert versus adressage fermé :
le pour et le contre
• Adressage fermé (chainage)
   • Peut gérer un nombre illimité d’éléments et
     de collisions
   • Performances plus stables
   • Surcoût lie a la gestion et le stockage en
     mémoire des listes liées
• Adressage ouvert
   • Rapide et peu gourmand en mémoire
   • Choix de la fonction de hachage plus difficile
     (pour éviter les grappes)
   • On ne peut pas avoir n > m
   • Suppression problématique
• D'autres alternatives existent :
   • Two-probe hashing
   • Cuckoo hashing
